# [T004] Валидировать state и active_error в heartbeat
- приоритет: средний
- статус: открыто
- теги: bug, server, validation

## Описание
В `heartbeat` значение `active_error` от устройства используется, если `state == 'ERROR'` и открытых записей в `device_errors` нет, и пишется в БД как есть. `state` не ограничен списком допустимых значений. Клиент может записать произвольные строки.

Что сделать:
- ограничить `state` перечнем (`IDLE`, `SELLING`, `ERROR`, при необходимости других) через `Literal`/`Enum` в модели `Heartbeat`;
- ограничить длину и набор символов `active_error` (или не доверять клиентскому значению вовсе и брать его только из `device_errors`);
- описать контракт в README.

Критерий готовности: некорректные значения дают 400/422.
