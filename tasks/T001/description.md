# [T001] Принимать SALE при нулевом остатке вместо ошибки 400
- приоритет: высокий
- статус: открыто
- теги: bug, server, inventory

## Описание
В `receive_event` (`src/mta_project/mta_server.py`, блок `event_type == "SALE"`) сначала вставляется запись в `sales`, затем `UPDATE inventory ... AND quantity > 0`. Если остаток нулевой, бросается `ValueError`, транзакция откатывается и клиент получает 400.

Проблема: автомат уже физически выдал товар, а сервер теряет продажу из учёта. Сервер должен быть источником правды по продажам.

Что сделать:
- принять продажу (запись в `sales` и `events` сохраняется) даже при нулевом или неизвестном остатке;
- зафиксировать расхождение (флаг/запись о нехватке остатка или предупреждение в ответе и логе), не уводя `quantity` ниже 0 (в схеме `CHECK (quantity >= 0)`);
- решить и описать поведение для неизвестного `product_id` (внешний ключ по-прежнему даёт 400);
- обновить README и проверку в `vending_emulator.py check`.

Критерий готовности: SALE при остатке 0 возвращает 200, продажа видна в мониторе, остаток остаётся 0.
