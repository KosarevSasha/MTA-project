# [T012] Разбить receive_event на обработчики по типам событий
- приоритет: средний
- статус: открыто
- теги: refactor, server

## Описание
`receive_event` занимает около 250 строк с одним `try` и длинной цепочкой `if/elif`. Это затрудняет чтение и тестирование.

Что сделать: вынести обработку в функции `apply_sale`, `apply_load`, `apply_unload`, `apply_error_set`, `apply_error_clear` с сигнатурой `(cur, event)`, а выбор делать через словарь обработчиков. Поведение и ответы API не менять.

Критерий готовности: логика прежняя, тесты (см. задачу про тесты) проходят.
